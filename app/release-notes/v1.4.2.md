# QuMesh 1.4.2

A Windows fix release. macOS and Linux builds are unchanged apart from
the version number.

## The Windows installer produced an app that couldn't start

Launching QuMesh after installing it on Windows failed straight away
with a system error: *"The code execution cannot proceed because
Qt6QuickControls2.dll was not found."* This affected every Windows
release up to and including 1.4.1.

The installer put every Qt DLL in `QuMesh\bin\`, but `QuMesh.exe`
lives one level up in `QuMesh\`. Windows looks for an app's DLLs only
next to the executable and on `PATH`, never in a subfolder, so it found
none of them. The Qt DLLs and `qt.conf` now install alongside
`QuMesh.exe`.

Thanks to @ilgrank for the report, and for the workaround that pointed
straight at the cause (#445).

**If you used the workaround** (copying the contents of `bin\` up into
the QuMesh folder), just install 1.4.2 over it. The installer replaces
those files with the same ones in the same place.

Our release pipeline missed this because its launch test ran on a build
machine where Qt's own DLLs were already on `PATH`. Every release now
silently installs the real Windows installer. It then checks that each
DLL the app or its plugins import is either next to `QuMesh.exe` or in
`System32`, and starts the app with Qt removed from `PATH`. Every pull
request runs the same check against a fresh install.

## Release page

The install instructions on the GitHub release page are now derived
from how each platform was actually signed. Previous release pages told
macOS users to bypass a Gatekeeper warning that the signed, notarized
app never shows (#443). The "full changelog" link now compares against
the previous release.

## Upgrading

- **Windows**: download `QuMesh-1.4.2-windows-x64.exe` from the
  Releases page and run it. *Check for Updates…* lives inside the app,
  so it can't help if QuMesh never started. If you used the workaround
  above, it works as usual.
- **macOS**: *Check for Updates…* from the QuMesh menu, or grab the
  `.dmg` from the Releases page. Nothing changed for macOS in this
  release.
- **Linux**: `sudo apt update && sudo apt upgrade qumesh` if you've
  added the repo (snippet in the v1.2.0 notes). Otherwise grab the
  `.deb` matching your distro and architecture from the Releases page.
  Nothing changed for Linux in this release.
